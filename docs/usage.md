# Usage

For why it works the way it does, see [how-it-works.md](how-it-works.md).

## Installation

Requires Rust 1.88+ and a C compiler — SQLite is built from source, so reading
an Atuin database needs no system library.

### Linux

```sh
sudo apt install build-essential      # Debian / Ubuntu
sudo dnf install gcc                  # Fedora
sudo pacman -S base-devel             # Arch

cargo install --git https://github.com/Mathieu135/shelfware
```

### macOS

```sh
xcode-select --install                # once, if never done
cargo install --git https://github.com/Mathieu135/shelfware
```

The binary lands in `$CARGO_HOME/bin` (`~/.cargo/bin` by default). Make sure
that directory is on your `PATH`.

## The whole tool

```sh
shelfware                     # the report
shelfware clean               # a removal script to review
shelfware completions zsh     # shell completion
```

That is the entire interface. Everything below is optional.

## The report

```sh
shelfware
```

No configuration needed. Every package manager present is inspected, history
is auto-detected (Atuin if its database exists, otherwise your shell's history
file), and the activity threshold calibrates itself to how much history you
have.

```
shelfware — 66 packages inspected

  active         11   Typed regularly at your prompt
  indirect       44   Executed recently, but not by you typing it
  rare            4   Typed occasionally, and not executed lately
  integration     1   Never executed, but wired into your shell config
  unused          6   No signal from any source — removal candidates

UNUSED — No signal from any source — removal candidates
  cargo-watch        cargo   never typed · last run 6mo ago
  imagemagick        brew    never typed · last run 5mo ago

Review these 2 first — no recent sign of use:
  cargo-watch imagemagick
```

The summary always describes the **whole** inventory. Below it, only the
categories you can act on are detailed — printing the fifty tools you obviously
use would bury the handful worth a decision. Add `--all` to see everything.

Each row ends with its evidence:

```
cloc          brew    typed 3× · last run 2mo ago
starship      brew    never typed · never run · in shell config
```

That is there so a verdict can be argued with rather than believed.

## The one setting worth knowing

```sh
shelfware --since 6mo
```

`--since` decides how far back an execution still counts as "in use". It
accepts `30d`, `6w`, `6mo`, `1y`, or a bare number of days, and defaults to
`30d`.

The default is deliberately tight, which is why `rare` and `unused` are framed
as "worth reviewing" rather than "delete this". Raise it if you keep tools you
legitimately touch a few times a year — release tooling, disaster-recovery
scripts, anything seasonal. On a typical machine the difference is large:

| `--since` | unused |
| --- | --- |
| `30d` (default) | 6 |
| `6mo` | 2 |

## Removing packages

```sh
shelfware clean > cleanup.sh
```

Writes a shell script instead of removing anything:

```bash
#!/usr/bin/env bash
# Generated by shelfware. Review it, delete what you disagree with,
# then run it. Nothing here executes on its own.
set -euo pipefail

# cargo-watch — never typed · last run 6mo ago
cargo uninstall cargo-watch

# @scope/some-tool — never typed · never run
#   NOTE: npm binary names are guessed, so "never typed" is weak
#   evidence here. Confirm this package is genuinely idle first.
npm uninstall -g @scope/some-tool
```

Review it, delete what you disagree with, run it. The evidence stays attached
to each command, so the decision is reviewable exactly where it is made.

The separation is deliberate: some verdicts rest on guessed binary names, and
every signal has a documented blind spot. An audit tool has no business
uninstalling anything on that basis.

Uninstall commands per manager:

| Manager | Command |
| --- | --- |
| brew | `brew uninstall <name>` |
| cargo | `cargo uninstall <name>` |
| pipx | `pipx uninstall <name>` |
| uv | `uv tool uninstall <name>` |
| npm | `npm uninstall -g <name>` |
| go | `rm -f <path>` — `go install` keeps no manifest |

## Shell completion

```sh
# zsh
shelfware completions zsh > ~/.cache/zsh/completions/_shelfware

# bash
shelfware completions bash > ~/.local/share/bash-completion/completions/shelfware

# fish
shelfware completions fish > ~/.config/fish/completions/shelfware.fish
```

`elvish` and `powershell` work the same way. For zsh, the target directory must
be on your `fpath` before `compinit` runs:

```sh
fpath=("${XDG_CACHE_HOME:-$HOME/.cache}/zsh/completions" $fpath)
```

On macOS with Homebrew's zsh, `$(brew --prefix)/share/zsh/site-functions` is
already on the `fpath`.

## Configuration

Optional, at `~/.config/shelfware/config.toml` (or under `$XDG_CONFIG_HOME`):

```toml
since    = "6mo"
ignore   = ["imagemagick", "cargo-watch"]
managers = ["brew", "cargo"]
```

All keys optional. Flags override the file, which overrides the defaults. A
malformed file warns on stderr and is ignored — a broken config never blocks an
audit.

`ignore` is the one worth using. It matches a package name or any binary it
provides, and it exists for permanent decisions: a tool you knowingly keep for
once-a-year use should stop being proposed at every audit.

## JSON

```sh
shelfware --json | jq
```

```json
{
  "packages": [
    {
      "name": "cargo-watch",
      "manager": "brew",
      "verdict": "unused",
      "interactive_hits": 0,
      "last_exec_days_ago": 34,
      "in_shell_config": false,
      "binaries": ["cargo-watch"]
    }
  ]
}
```

`last_exec_days_ago` is `null` when no access time could be read.

```sh
# removal candidates, by name
shelfware --json | jq -r '.packages[] | select(.verdict=="unused") | .name'

# anything untouched for over six months
shelfware --json | jq -r '.packages[] | select(.last_exec_days_ago > 180) | .name'
```

## Running it regularly

Monthly is the right cadence — tool drift is slow, and running it weekly mostly
shows you the same list.

```cron
0 9 1 * * shelfware --json > ~/.local/state/shelfware/$(date +\%Y-\%m).json
```

Keeping the JSON makes drift visible:

```sh
diff <(jq -r '.packages[]|select(.verdict=="active")|.name' 2026-06.json) \
     <(jq -r '.packages[]|select(.verdict=="active")|.name' 2026-07.json)
```

## Advanced options

Hidden from `-h`, documented in `--help`. You are unlikely to need them.

| Option | Purpose |
| --- | --- |
| `--only <VERDICT>` | Restrict the listing to one verdict. With `clean`, picks which category to remove |
| `--managers <LIST>` | Inspect a subset of `brew,cargo,uv,pipx,npm,go` |
| `--ignore <LIST>` | Omit packages for this run only |
| `--history <PATH>` | Read explicit history sources instead of auto-detecting |
| `--active-hits <N>` | Override the auto-calibrated activity threshold |

`--active-hits` is derived from your history size by default — one per thousand
recorded command invocations, clamped to 3..50. A fresh machine cannot clear
the same bar as one with years of history, and asking users to work that out is
why it stopped being a visible flag.

`--history` is useful for auditing history copied from another machine, but
note that access times still describe the local one, so treat `indirect` with
suspicion in that mode.

## Exit status

`0` on success, including when nothing is found. Non-zero for an actual
failure, such as an unparseable `--since`. A missing package manager is not an
error: it simply contributes nothing.
